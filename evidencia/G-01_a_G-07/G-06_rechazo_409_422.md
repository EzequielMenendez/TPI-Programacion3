# Evidencia · Caso G-06: Rechazo de Venta (`409` y `422`), Preservación de Borrador e Historial Inalterado

## Objetivo de la Consigna
> Probar un ID inexistente (`409`), stock insuficiente (`409`) y renglones repetidos (`422`). El borrador se conserva y el historial queda igual.

---

## 1. Rechazo por Libro o Cliente Inexistente (`409 Conflict`)

- **Petición emitida (libro inexistente `999`)**:
  ```http
  POST /api/ventas/ HTTP/1.1
  Content-Type: application/json

  {
    "cliente_id": 2,
    "renglones": [
      { "libro_id": 999, "cantidad": 1 }
    ]
  }
  ```
- **Respuesta del servidor (`409 Conflict`)**:
  ```json
  {
    "detail": "No existe el libro con id 999."
  }
  ```
- **Petición emitida (cliente inexistente `999`)**:
  ```http
  POST /api/ventas/ HTTP/1.1
  Content-Type: application/json

  {
    "cliente_id": 999,
    "renglones": [
      { "libro_id": 2, "cantidad": 1 }
    ]
  }
  ```
- **Respuesta del servidor (`409 Conflict`)**:
  ```json
  {
    "detail": "El cliente indicado no existe."
  }
  ```

---

## 2. Rechazo por Stock Insuficiente (`409 Conflict`)

- **Petición emitida (solicitando cantidad superior al stock disponible del libro 5, stock = 3)**:
  ```http
  POST /api/ventas/ HTTP/1.1
  Content-Type: application/json

  {
    "cliente_id": 1,
    "renglones": [
      { "libro_id": 5, "cantidad": 50 }
    ]
  }
  ```
- **Respuesta del servidor (`409 Conflict` — restricción `ck_libro_stock_no_negativo`)**:
  ```json
  {
    "detail": "No hay stock suficiente para alguno de los libros."
  }
  ```
- **Resultado observado en la interfaz**:
  - Se despliega la alerta en `#ventas-errores`: **`No hay stock suficiente para alguno de los libros.`**
  - **El borrador de la venta se conserva intacto en pantalla** (cliente seleccionado y renglones con sus cantidades) para que el usuario ajuste la cantidad sin rearmar la venta.

---

## 3. Rechazo por Cuerpo Fuera de Contrato / Renglones Repetidos (`422 Unprocessable Entity`)

- **En la interfaz**: si el usuario intenta agregar dos veces el mismo libro al borrador, la validación cliente lo impide informando el error sin alterar la cantidad existente.
- **Contra la API (`POST /api/ventas/` con `libro_id` repetido en dos renglones)**:
  ```http
  POST /api/ventas/ HTTP/1.1
  Content-Type: application/json

  {
    "cliente_id": 1,
    "renglones": [
      { "libro_id": 1, "cantidad": 1 },
      { "libro_id": 1, "cantidad": 2 }
    ]
  }
  ```
- **Respuesta del servidor (`422 Unprocessable Entity`)**:
  ```json
  {
    "detail": [
      {
        "type": "value_error",
        "loc": ["body", "renglones"],
        "msg": "Value error, Un mismo libro no puede aparecer en dos renglones."
      }
    ]
  }
  ```
- **Verificación del historial (`GET /api/ventas/`)**:
  - El listado de ventas en `#historial` permanece exactamente igual (sin registros huérfanos ni modificaciones de stock).
